# Restaurant Monthly Revenue Prediction

## Business Problem

Restaurant managers need to estimate expected monthly revenue before making decisions related to **promotions, pricing, delivery strategy, seating capacity, customer experience, and outlet planning**.

Revenue is influenced by several factors at the same time, so relying on only one variable can lead to weak decisions. This project uses **Multiple Linear Regression** to estimate `Monthly_Revenue` from operational, customer, marketing, cuisine, and location-related variables.

The final model is integrated into a **Streamlit decision-support dashboard** that not only predicts revenue, but also benchmarks outlet performance, highlights business-health signals, evaluates model-based what-if scenarios, and provides managerial recommendations.

---

## Project Objective

The objective is to build a complete regression solution that moves from raw business data to a deployment-ready application.

The workflow includes:

1. Dataset generation and preparation  
2. Data-quality checks  
3. Exploratory analysis  
4. Multiple Linear Regression assumption testing  
5. Model training and evaluation  
6. Cross-validation  
7. Saving the final trained model  
8. Deployment through Streamlit  
9. Business interpretation and decision support  

The application is designed to help answer two practical questions:

> **What monthly revenue can this outlet be expected to generate?**

and

> **Which business levers are associated with better predicted revenue?**

## Dataset Generation Word File

`DatasetCoPilotPrompt.docx` is the supporting **Word file** that documents the prompt/specification for generating the restaurant dataset.

It specifies:

- exactly **2,000 restaurant records**,
- exactly **11 columns**,
- realistic Indian restaurant business variables,
- realistic relationships between predictors and revenue,
- moderate data-quality issues for cleaning and EDA,
- controlled missing/inconsistent values,
- realistic outliers,
- and sufficient random variation so the regression is not perfectly predictable.

The Word file also specifies that `Monthly_Revenue` should broadly depend on customer volume, average bill value, delivery activity, location, promotions, cuisine and random business conditions rather than being generated by one perfectly deterministic formula.

---

## Dataset

The dataset contains **2,000 restaurant outlet records** and 11 original columns:

1. `Outlet_ID`
2. `Cuisine_Type`
3. `Location_Type`
4. `Average_Daily_Customers`
5. `Average_Bill_Value`
6. `Delivery_Order_Percentage`
7. `Seating_Capacity`
8. `Employee_Count`
9. `Promotion_Spend`
10. `Customer_Rating`
11. `Monthly_Revenue`

The dataset-generation specification requires realistic customer counts, bill values, delivery percentages, seating capacity, staffing, promotional expenditure, customer ratings and revenue for restaurant outlets.

### Variables Not Used in the Final Model

- `Outlet_ID` was excluded because it is only a unique identifier.
- `Employee_Count` was removed after the multicollinearity/VIF analysis because it overlapped strongly with outlet scale-related variables.

## Model Training Notebook

`model_training.ipynb` contains the complete modelling workflow.

### Part A — Data Preparation and Regression Assumptions

The notebook includes:

- missing-value checks,
- duplicate checks,
- impossible-value checks,
- inconsistent category checks,
- feature and target identification,
- linearity analysis using scatterplots,
- correlation analysis,
- Variance Inflation Factor (VIF),
- multicollinearity correction,
- categorical encoding,
- residual calculation,
- mean residual check,
- residual sequence plot,
- Durbin–Watson statistic,
- residual-vs-fitted analysis,
- Goldfeld–Quandt test,
- Bartlett test,
- Breusch–Pagan test,
- residual histogram,
- Q-Q plot,
- Jarque–Bera test,
- standardized residuals,
- Cook's Distance,
- and re-checking assumptions after corrective action.

### Part B — Model Building and Evaluation

The final primary model is **Multiple Linear Regression**.

The model is evaluated using:

- R²
- Adjusted R²
- MAE
- MSE
- RMSE
- residual analysis
- 5-Fold K-Fold Cross-Validation

The original project workflow also covers data preparation, assumption testing, model building, final-model saving and Streamlit deployment.

### Part C — Saving the Model

The final preprocessing + regression pipeline is saved as:

`model.pkl`

This allows the web application to load the trained model directly instead of retraining it every time the app starts.

### Part D — Streamlit Application

The trained model is integrated into `app.py` to provide an interactive business-facing application.

## Reference Model Performance

Using the reference **80:20 train-test split**, the model produced approximately:

| Metric | Result |
|---|---:|
| R² | **0.949** |
| Adjusted R² | **0.946** |
| MAE | **₹1.36 lakh** |
| RMSE | **₹1.73 lakh** |

An R² of approximately **0.949** indicates that the model explains about **94.9% of the variation in Monthly Revenue** in the reference test dataset. The uploaded project README reports the same reference evaluation metrics.

## Revenue Benchmark Categories

After generating a prediction, the application classifies the outlet into one of four performance groups:

- **Below Benchmark**
- **Developing**
- **Strong**
- **Top Quartile**

This allows a manager to interpret the predicted revenue relative to the training dataset rather than looking at the revenue figure in isolation.

---

## What-If Business Scenarios

The dashboard evaluates model-based scenarios such as:

- increasing daily customers,
- increasing average bill value,
- increasing delivery share,
- increasing promotion spend,
- improving customer rating,
- and increasing seating capacity.

These scenarios are ranked according to their **model-predicted change in monthly revenue**.

The purpose is to help management identify which controllable business variable may deserve further investigation.

---

## Important Interpretation

This application is a **decision-support tool**, not a causal forecasting system.

Regression-based recommendations and what-if scenarios represent **statistical associations learned from the dataset**. They do not prove that changing an input will automatically cause the exact predicted revenue change.

For actual managerial decisions, the model output should be combined with:

- contribution margin,
- food cost,
- labour cost,
- customer acquisition cost,
- operating capacity,
- competitor activity,
- and local market conditions.
